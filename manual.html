BOARDSCOPE
USER MANUAL — v5.4.1

BoardScope is a PCB repair diagnostic workbench. Load boardview files and schematics side-by-side, measure components with a live USB multimeter or oscilloscope, trace signal paths, run AI-powered diagnoses, manage repair jobs, generate invoices, automate test sequences, and collaborate with remote technicians — all in one tool.

Overview

BoardScope combines four workspaces into a single window:

📋 Schematic / PDF

View, annotate, and search multi-page schematics with bookmarks and highlights.

🔌 Board View

Interactive top/bottom layer view with net highlighting, component search, and color maps.

⚡ Live Multimeter

USB serial meter integration — live readings, auto-capture, voltage rail detection, diode database.

🤖 AI Diagnosis

Send board context and measurements to Claude, GPT-4o, Gemini, or a local model for repair suggestions.

🌡 Thermal & Damage Maps

Align thermal camera photos over the board view, and mark corroded/missing/burned components.

🔴 Known-Bad Database

Built-in warnings for commonly failing components, cross-references, and guided MOSFET testing.

📋 Shop Management

Repair queue, job tickets, parts inventory, time tracking, customer reports, and invoice generator.

Supported browsers: Chrome 89+ or Edge 89+ (required for Web Serial API used by the multimeter and WebUSB for oscilloscopes). Safari and Firefox do not support Web Serial or WebUSB.

Installation

Desktop App (macOS)

Download the latest .dmg from the releases page, open it, and drag BoardScope into your Applications folder. Since the app is signed with an official Apple Developer ID, it should run immediately. If blocked, right-click the app and choose Open.

Desktop App (Windows)

Download the .exe installer. Run the setup and follow the prompts. BoardScope will be installed to your local AppData folder and a shortcut created on your desktop.

Desktop App (Linux)

Download the .AppImage or .deb file. For AppImage, right-click the file, go to Permissions, and check Allow executing file as program, then double-click to run.

Web Version

Open boardview.html directly in Chrome or Edge. No server or internet connection is required for core features. AI diagnosis requires an API key.

API Key Setup (for AI features)

Create a file named api key in the app folder (or paste your key into Settings → AI). The file supports multiple providers:

ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
GEMINI_API_KEY=AI...
OPENROUTER_API_KEY=sk-or-...

For local models (Ollama / LM Studio), no key is needed — just set the base URL in AI settings.

Multimeter

Requirement: Web Serial API — Chrome 89+ or Edge 89+ only. Connect your meter via a USB-to-serial adapter.

Supported Meters

BoardScope supports three multimeter protocols, auto-detected from the first valid frame:

FS9721 Protocol (2400 baud, 14-byte frames)

  • UNI-T UT61E, UT61D, UT60E, UT60A
  • Victor VC86, VC82, VC81
  • Mastech MS8250D, MS8230D
  • Voltcraft VC-820, VC-840
  • Digitech QM-1531
  • Lilliput DM25, T-28
  • Many Chinese FS9721 clones

OWON Protocol (9600 baud, 11-byte frames)

  • OWON OW16B, OW16C
  • OWON-compatible USB serial meters

Metex Protocol (1200 baud, 14-byte ASCII frames)

  • Metex M-3860M
  • Voltcraft M-3860
  • Conrad ME-32

Connecting

  1. Plug your meter's USB adapter into the computer
  2. Click the ⚡ METER button (header), select TOOLS ➔ 🔌 Multimeter from the menu, or press M to open the meter window
  3. Click CONNECT — the browser's port picker appears
  4. Select your meter's COM/serial port and click Connect
  5. The status line shows Connected and live readings begin

Auto-Net: Probe → Board Highlight

This is the fastest way to identify what you're touching on a real board without hunting for a silk-screen label.

Requires: OBD data loaded for the current board (so BoardScope has reference voltages to compare against).

Workflow

  1. Load OBD data for your board (REPAIR → OBD DATA → Import)
  2. Connect your meter and click NET in the meter window — it turns green (NET ✓)
  3. Touch your probe to any test point or via on the physical board
  4. When the reading stabilises, BoardScope compares the voltage against every net in the OBD data
  5. If a match is found within 6% tolerance, that net highlights on the board — you see every pin and component on that rail instantly
  6. The status bar confirms: NET MATCH ⚡ PP3V3_G3H = 3.30V (measured 3.281V)

If multiple rails share the same voltage (common with 3.3V or 1.8V), BoardScope highlights the closest match and lists the others in the status bar so you can choose.

Diode Drop Database

In DIODE / CONT mode, readings are matched against a reference database:

StatusConditionAction
SHORT< 0.050 VLikely shorted junction — inspect for damage
OPEN> 2.0 V (OL)Open circuit — component may be lifted or dead
NORMALWithin reference rangeShows matched reference name (e.g. CPU_VCC, USB_DATA)

Stable Reading Detection

A reading is considered stable when the value stays within 1% tolerance for 1 second. Stable readings are highlighted in the display and used for auto-capture. The debounce window and tolerance are adjustable in code (setStableWindow(ms), setStableTolerance(pct)).

Calibration

Per-mode calibration offsets can be applied to compensate for lead resistance or meter drift. Set via Settings or programmatically with meter.setCalibration('OHM', -0.5).

Probe Mode

Probe Mode turns BoardScope into a measurement logging tool. Enable it via PROBE MODE in the REPAIR dropdown.

Two Ways to Work

There are two approaches depending on whether you know the component reference or not:

ApproachWhen to useHow
Component-firstYou know the ref (e.g. U2, C104) and want to measure itSearch the ref → click the pad → probe with meter
Net-firstYou're probing a random point on the physical board and need to know what it isEnable NET on the meter window → probe the point → the matching net highlights automatically

Component-First Workflow

  1. Enable Probe Mode — the cursor changes to a crosshair over pads
  2. Click any pad on the board to open the measurement entry for that net
  3. Enter V (voltage), D (diode drop), or R (resistance) values manually, or enable FILL on the meter window to auto-populate from the live meter
  4. Press Enter to save the measurement
  5. The pad changes color to reflect pass/fail status against the OBD reference

Net-First Workflow (with USB Meter)

  1. Load OBD data and connect your USB meter
  2. Enable NET in the meter window
  3. Touch your probe to any test point or via on the real board — no need to find the component ref first
  4. When the reading stabilises, the matching net highlights on the board — all connected components become visible
  5. Click any highlighted pad to log the measurement to that net

Auto-Capture

With CAP enabled on the meter window, any stable reading is automatically saved to the currently selected net without you needing to click. Touch a pad to select the target net, then probe — readings are captured hands-free.

Measurement Comparison

Open MEAS. TABLE to see all your logged measurements alongside the OBD reference values in a single table. Filter by component ref, sort by deviation.

Before / After Snapshot

Click 📷 SNAP in the probe mode bar to save the current set of measurements as a baseline. After further probing, open ▲ BEFORE/AFTER DIFF in the REPAIR dropdown to see exactly what changed. See the Before / After Diff section for full details.

Continuity Checker

Open via CONTINUITY in the FIND dropdown. Measures resistance between two selected points on the board.

  1. Click Point A — click a pad to set the first test point
  2. Click Point B — click a second pad to set the second test point
  3. Press Enter to measure, or enable live meter for auto-reading
  4. Result shows resistance value; < 1Ω is typically a good connection
  5. Press Escape to close

Short Circuit Finder

Open via SHORTS in the FIND dropdown. Scans measurements for potential short circuits between nets.

  • Adjustable resistance threshold — readings below the threshold are flagged as potential shorts
  • Results listed by net pair with measured values
  • Click any result to highlight the involved nets on the board
  • Color-coded severity: red = likely short, amber = suspicious

Fault Tree

Open via FAULT TREE in the REPAIR dropdown. An interactive decision tree that guides you through a structured diagnostic workflow.

  • Each node presents a test or observation question
  • Answer Yes / No to advance through the tree
  • Leaf nodes suggest probable causes and repair actions
  • Integrated with Probe Mode — some nodes auto-select the relevant net on the board
  • Pre-built trees for common board faults across multiple manufacturers

OpenBoardData (OBD)

OpenBoardData provides community-sourced reference measurements for boards — expected voltages, diode drops, and resistance values for each net on a known-good board.

Using OBD Data

  1. Open OBD DATA from the REPAIR dropdown
  2. Import an .obdata file for your board model
  3. Reference values appear in pin popups and the net info panel
  4. The Heat Map overlay uses OBD data to color-code deviations
  5. The MEAS. TABLE shows your readings next to OBD reference values

Contributing Measurements

After measuring a known-good board, export your measurements via OBD DATA → Export to generate an .obdata file that can be shared with the community.

Fail-Safe Offline & Redirect Protection

In the event of local DNS issues, proxy redirects, or strict protocol restrictions (such as running over file:// protocol directly), BoardScope incorporates a three-stage automatic failover system:

  • Relative Local Fetch: The app first requests OBD board lists or proxy files through local relative paths.
  • Absolute Local Loopback: If the relative call is blocked, the app automatically reroutes requests to the local Electron/Express server at http://127.0.0.1:8080, which bypasses local file-protocol limits.
  • Cloud Fallback: If both local options fail, BoardScope seamlessly falls back to querying the official cloud database on https://boardscope.ca.

Additionally, the backend proxy automatically follows recursive HTTP 301/302 redirects, making downloads immune to any future server movements or protocol upgrades from OpenBoardData.

Power Sequencing Timeline

Open via ▶ POWER SEQUENCE in the BOARD dropdown. Shows the exact order in which power rails must come up on a given board model, with live measurement status overlaid on each step.

How to Use

  1. Open the panel — it auto-selects the board model if it matches the loaded file name
  2. Use the board model selector to manually pick a model
  3. Each numbered step shows the rail name, net, expected voltage, and any measurement you've already taken
  4. Steps with a live reading show ✓ or ✗ depending on whether the reading is within tolerance
  5. Work through the sequence top-to-bottom — the first step that's missing or wrong tells you where to focus

Tip: Take measurements in Probe Mode first, then open the Power Sequence panel — all your readings will already be overlaid on the timeline.

Supported Board Models

  4. Click ▶ PLAY to replay the sequence

Recordable Actions

  • Search — component or net search
  • Select Component — click a component by reference
  • Click Pad — click a specific pad/pin by net name
  • Measure — wait for a stable multimeter reading
  • Save Measurement — log the reading to the current net
  • Zoom — fit view or zoom to component
  • PDF Page — navigate to a specific schematic page
  • Toggle Side — switch top/bottom layer
  • Wait — configurable delay between actions

Export / Import

Macros are stored as JSON and can be exported as .macro.json files for sharing. Import via the 📥 IMPORT button.

Post-Repair Test Suite

Automated test sequences to verify repairs before returning devices to customers. Access via ✅ TEST SUITE in the BOARD dropdown.

How It Works

  1. Select a test suite matching your board model (or use the generic Quick Power Check)
  2. Click RUN — the suite executes each test in sequence
  3. Each test highlights the target net on the board and waits for a stable multimeter reading
  4. Results are compared against expected values with configurable tolerance
  5. A pass/fail report is generated with all measurements

Team Collaboration

Share your BoardScope session with a remote technician in real-time using WebRTC peer-to-peer connections. Access via 👥 COLLABORATE in the header.

How It Works

  1. Click CREATE SESSION — a 6-digit room code is generated
  2. Share the room code with your remote technician
  3. The remote technician opens BoardScope, clicks JOIN SESSION, and enters the code
  4. Both screens sync in real-time: board view, PDF page, component selections, measurements, and annotations

Features

  • State synchronization — board position, zoom, selected component, highlighted nets, PDF page
  • Cursor sharing — see your partner's cursor position with a colored indicator
  • Chat — text messages between participants
  • Annotation sharing — PDF annotations appear on both screens
  • Host/Participant roles — host sends initial state to new joiners

Network: Collaboration uses WebRTC with Google STUN servers for NAT traversal. Both participants need Chrome or Edge (WebRTC support). No data is sent to any server — all communication is peer-to-peer.
